# Go2 单房间自由探索与找物最小改造计划

- 日期：2026-11-07
- 状态：软件改造与离线验证已实施；现场验收待执行。详见 [实施记录](2026-11-07-go2-search-implementation.md)。本计划的实机退出条件尚未全部满足。
- 设备：Unitree Go2 Air，用户确认硬件版本 2.0，2025 年购买；固件版本尚未单独确认。
- 部署：现有云服务器通过 WebRTC Remote 连接机器狗，不在同一局域网。
- 场景：用户指定的单房间或有限空间，平地、摄像头可以看见的地面物品；目标包括范围内自主探索，以及接受任务后找到物品、报告、走到附近。
- 总体选择：在 SSM 现有模块内实现，选择性迁移最新版 dimos 的算法；首版不新增导航微服务、中间件或 Agent 运行时。

## 1. 交付目标与成本边界

最终交付两种行为，共用地图、导航、观察记录与任务执行能力：

1. **自由探索**：主动选择有信息价值的位置和朝向，扩大地图、查看未观察区域；减少重复访问，遇到阻塞会换目标或说明原因，完成覆盖后降低活动频率。
2. **任务找物**：用户说“在屋里找猫头鹰并走到附近”后，持续搜索可达空间；发现候选后确认、报告、定位、导航到附近，再根据实际反馈确认完成。

在用户指定的单房间或有限空间内完成任务，就是最终交付目标。探索和验证均限于该范围，不要求跨房间搜索或验证。

搜索仅覆盖指定范围内可到达、可观察的区域。家具完全遮挡的区域要记录为未检查，不能声称物品不存在。地图未知边界耗尽、任务预算耗尽、路径受阻是不同结束原因；发现门口或范围外的未知区域不代表需要继续向外探索。

### 首版必须做

- 同一定位会话内的地图累积、观测证据融合与局部障碍更新。
- 全图候选选点，分离几何探索与相机搜索覆盖。
- 同一工作流支持自由探索和指定物品搜索。
- 地面目标定位、导航到附近、到位复核。
- 任务取消、断链处理、真实回执、搜索进度和结果展示。
- 指定单房间或有限空间内的实机验收，以及云端链路条件下的性能验证。

### 按验收结果决定是否引入

- ICP／PGO 回环校正：仅在同会话地图漂移确实影响指定空间内的搜索或到位判定时评估引入；单房间测试通过即可不引入。
- 软代价 A*、更复杂的路径跟随：现有导航出现贴障碍、反复卡住等可复现问题时，按问题迁移对应模块。

### 暂缓

- 跨重启复用地图、自动重定位、自动充电。
- 自动房间命名、家具关系图、向量数据库、通用语义地图平台。
- 新增 ROS 2、LCM、完整 dimos runtime、通用导航插件框架或第二套 LLM 决策循环。
- 外置传感器、本地 GPU 大模型、强化学习导航。

暂缓项不作为单房间交付前提；如果实测出现定位问题，先诊断修正，只有确认需要回环校正时才执行相应增强阶段。

## 2. 已核实的基础与问题

### 可以直接复用

- `cloud/go2/connection/`：Remote 连接、视频、odom、点云接收及遥测新鲜度。
- `cloud/go2/navigation/astar.py`：八邻域 A*、Octile 启发式、禁止对角穿障碍拐角。
- `cloud/go2/navigation/navigator.py`：导航任务、里程计反馈、停止与重规划入口。
- `cloud/go2/control.py`、`execution.py`、`tasks.py`：控制租约、执行上下文、任务归属与取消机制。
- `cloud/agents/common/`：LangGraph 运行、文件检查点、动作账本和结果投影。
- 当前视觉模型与 `visual_lidar_navigate.py`：目标识别、RGB／LiDAR 配对、停靠点和视觉复核的业务入口。
- 现有 MQTT Card／status、HTTP 调用和 SSE 进度链路。

### 本次调查得到的事实

- 短时在线抽样曾取得约 18.8 Hz odom、7.7 Hz 雷达体素、640×360 视频，避障开关返回开启。这不是长期性能或实际避障效果验收。
- 现有探索是 Dijkstra 可达搜索加局部未知格启发式；候选受 0.5～1.5 米距离、邻近未知格、原地转身条件共同约束。
- 一份真实样本中，807 个邻近未知区域的候选被转身方向限制压缩到 3 个；转身圆盘内无实测障碍，但 29 个格缺少地面观测。对同一份点云改变少量朝向，目标可在 `None` 与有效坐标之间跳变。
- 原来的所有 `null` 没有完整同帧回放，不能归为同一个原因；上述样本已足以成为新设计的回归用例。
- 当前地图主要由最新包重建；几何已知区域与相机已搜索区域没有独立表示。
- 可见目标导航工具是终止工具；当前流程没有“目标没看到就换观察点继续找”的完整任务。
- 相机定位仍使用临时参数；不能把 bbox 内的全部高于地面雷达点直接等同于目标本体。

新实现不沿用旧探索的距离／方向硬筛选结构。旧实现仅用于复现问题和比较效果。

## 3. 最小实现结构

```text
现有 Remote 连接
    ├─ 点云＋odom → 会话地图与最新局部障碍 → 现有 Navigator／A*
    └─ 图像＋拍摄位姿 → 目标检测与观察记录

现有 Go2 LangGraph
    → 统一探索／搜索工作流
    → 选择候选观察点 → 导航 → 观察 → 更新记录 → 继续／确认／结束

所有动作继续经现有控制租约和唯一运动出口执行
所有进度继续经现有任务事件与 SSE 展示
```

算法组件使用普通 Python 类、函数和现有数据结构。必要的坐标／字段转换在接收与调用位置完成，不为这些转换建立服务层。

### 旧代码复用与清理

清理是本次能力改造的交付内容，不留到无期限的后续整理。先核对实际引用，再把仍有用的计算与契约迁入唯一归属位置；替代流程验证通过后，在同一阶段删除失效实现。

| Remote 连接、遥测、控制租约、身份权限、身体／生活状态、任务与动作账本 | 保留并复用；不因探索重写而删除 |
| `astar.py`、`navigator.py` | 保留有效基础；修改地图接入与执行行为，删除本次替换后不再使用的分支 |

| `mode/free_explore.py` 的旧目标选择、单点执行和重复决策逻辑 | 生命周期及用户介入入口保留；决策迁入统一工作流，旧决策主体删除 |

| `tools/tools.py` 的 `_locate_visible_target`、`_go2_precise_navigate_to_visible_target` 等旧流程 | 标定投影等有效能力合并到 perception；运动执行合并到 target_approach；工具文件只留薄调用入口 |

| 测试、诊断与调试脚本 | 保留有效行为用例与必要回放工具；更新导入和路径；删除只绑定废弃内部实现的测试及一次性对照脚本 |

已有明确的依赖不能误删：当前 `visual_lidar_navigate.py` 和诊断路由仍从 `visual_approach.py` 引用图像保存／目标偏移辅助函数，因此“旧文件名”不等于“整文件无用”。历史地面投影逻辑也可能被新方案复用，应迁移有效计算，删除重复编排，而不是整段丢弃。

删除前使用 `rg` 核对直接引用、工具注册表、字符串技能名、路由、提示词、动态调用及测试；“搜索不到 import”不能单独证明无用。删除后执行受影响模块的导入／测试收集和行为回归，检查既有可见目标导航与新找物入口均指向同一个接近执行器。

### 代码组织与规范

| 目录 | 唯一职责 |
|---|---|
| `cloud/go2/connection/` | 传输、接收和传感器时间／坐标元信息 |
| `cloud/go2/perception/` | 识别、测量、目标定位与观测证据；不执行行走 |
| `cloud/go2/navigation/` | 地图、覆盖、候选点、路径、接近执行和运动几何检查 |
| `cloud/agents/go2/workflows/` | LangGraph 任务顺序、搜索阶段、预算与结果组织；不复制地图算法或直接操作 WebRTC |
| `cloud/go2/mode/` | 模式许可、启动／暂停／中断接线；不保存第二套搜索决策 |
| `cloud/go2/tools/`、`router.py` | 工具声明、参数／上下文校验和薄调用；不承载探索或视觉导航算法 |
| `cloud/go2/tests/`、`cloud/agents/go2/tests/` | 分别放设备业务与工作流测试；改造涉及的散落检查文件按职责收拢 |
| `scripts/` | 必要的录制、回放与诊断入口；不成为运行期算法的依赖 |

- 同一业务行为只有一个实现。自由探索与找物共用选点和接近代码，不新增 `v2`、`new`、`legacy` 并行版本长期共存。
- 共用辅助函数放在现有职责模块并提供明确接口，不跨模块引用带下划线的私有函数；不为几段辅助代码创建无边界的 `utils.py`／`manager` 层。
- 机器人尺寸与几何余量、相机标定、任务预算各有唯一来源。任务模式不能在工具、Graph 和控制器里分别硬编码一套相同数值。
- 复用现有类型约定，对跨模块的位姿、地图快照、候选点和结果给出清晰类型与字段说明；长度用米、角度用弧度，坐标系／会话及时间语义明确。
- Python 使用 `snake_case`，常量使用 `UPPER_SNAKE`；导入方向按上表职责组织，避免循环依赖和在函数内隐藏职责混杂。
- 新增测试集中到上述 tests 目录。迁移现有 `*_checks.py` 时同步更新运行命令和相关文档，不复制同一组测试到两个位置；P0 基线命令仍以改造前实际路径为准。
- 删除实现时同步更新当前说明与公开能力；历史验收记录可以保留，但标明其对应的旧版本，不让用户按失效入口操作。
- 原文件改名或移动必须完成所有调用方迁移，回退依靠版本记录和 manual 模式，不靠长期保留一套旧自主执行器。

## 4. 数据与行为约定

### 4.1 地图

- 导航格保留 `free / occupied / unknown`；另记录观测来源、最近更新时间和证据可信度，不能把“没收到点”直接当自由或障碍。
- 首版累积二维地图即可；原始局部三维点云继续供目标定位使用，不先维护另一套完整三维语义地图。
- 只更新有可靠观测依据的区域。不能把整个点云包的矩形包围盒当成可见自由区域，也不能把预处理体素当原始激光束随意清障。
- 静态自由证据跨帧保留；新观测到的障碍立即进入局部地图。旧障碍仅在存在可靠清除证据时移除，不能只按时间自动变自由。
- `frame_id`、定位会话、地图版本与观测时间进入快照。地图合并不重复变换已经位于 odom 中的点。
- 每个规划步骤读取一个一致快照，不允许地图在一次搜索中途被另一线程原地改写。
- 坐标会话变化时停止当前运动并使旧地图／观察坐标失效。首版不允许凭持久化文件继续使用旧 odom 点位。
- 地图融合、全图搜索和图像推理不能阻塞 WebRTC 接收或速度控制；复用现有执行设施，用有界队列丢弃过时待处理帧，不新建任务调度框架。

### 4.2 观察覆盖

首版用任务内有界列表或栅格记录即可，不引入数据库：

`map_session + pose(x,y,yaw) + image_time + quality + visible_area + target_result`

- 几何自由不等于已搜索。原地改变朝向后看到的新区域也计入有效观察。
- 只有图像足够清晰、距离合适且没有被已知障碍遮挡的区域，才计为已观察；无法确认的部分保持未充分观察。
- 没看到目标只更新当前实际可见区域的搜索记录，不证明遮挡后的物品不存在。
- 已看到区域保留时间戳；自由探索可按变化或时间重新检查，指定找物任务优先完成尚未检查的区域。
- 不做房间自动分割或门口拓扑。观察点只在用户指定的搜索范围内生成；这里的“全图”指该单房间或有限空间的累积地图。

### 4.3 观察点选择

候选包含位置、朝向、来源和预期收益，而不只是 `(x,y)`：

- 未知边界附近的已知可达观察点；
- 已知空间中可观察到未搜索地面的点；
- 需要复核疑似目标的点。

步骤为“生成候选 → 几何可达性验证 → 综合评分 → 保持／切换目标”。评分包含新增视觉覆盖、地图信息、目标线索、路径成本、重复访问和执行难度。几何收益先有可解释的确定性实现；首版不依赖 LLM 对每个候选打分。

不把远处目的地限制为短段距离。目的地可在全图范围内，执行端根据新鲜局部地图分段或持续跟随并重规划。

目标保持机制用于减少抖动：仅在目标到达、失效、明显无进展、发现目标物品或有显著更好候选时切换。停止／取消永远优先，不受保持机制限制。

不存在 frontier 时继续检查视觉覆盖；不存在可达观察点时，返回具体原因，而不是无限重试或随机移动。

### 4.4 地面与转身

- 分开表达“实测障碍阻挡”与“地面证据不足”。
- 在平地假设下允许根据多帧一致地面及邻域平面证据填补小缺口；限制范围和可信度，不能跨障碍、遮挡边界或大块未知区域填充。
- 转向检查机身实际扫过的范围，而不把任意角度转向都等价成完整一圈。保留明确碰撞检查。
- 证据不足时先等有限数量新观测；仍不足则尝试去几何确认可达、可以转向的位置。没有安全恢复路径时暂停并说明。
- 不以模型“看起来空旷”绕过几何检查，也不把全部未知格当自由。

### 4.5 LangGraph 工作流与任务生命周期

一个工作流支持 `explore` 与 `find_object`，不增加自研 `while LLM -> tool` 循环。主要阶段：

`准备 → 当前位置有效观察 → 更新覆盖 → 选择下一观察点 → 导航 → 停稳观察 → 更新覆盖`

发现候选后转入：

`确认目标 → 报告发现 → 定位与选停靠点 → 导航接近 → 复核 → 完成`

- 状态最少包含目标描述、任务／地图会话、阶段、当前观察点、覆盖摘要、候选目标、最近回执、失败原因、时间／路程／步数预算。
- 大图像和点云不写入 Graph checkpoint；状态引用有界工件／地图版本。
- 通过现有任务注册表持有长任务，使用共享检查点与动作账本。HTTP 超时不等于任务完成。
- 找物工具明确声明 `motion=True`，角色与现有坐标导航一致（admin／visitor），不依赖 `ToolSpec` 的默认值。每一步沿用原用户、会话、`ExecutionContext` 和凭据有效期；到期即停止推进，不借 `SYSTEM_CONTEXT` 延长授权。visitor 仅保留任务内临时记录，不写管理员长期记忆；永久保存仍服从现有 `persist` 约束。
- 单次找物可以在 manual 配置下执行，不需要开启永久自由探索。自由探索的开启权限继续沿用现有管理员限制。
- 搜索子图由同一个服务端任务托管直到结束，保持生活任务归属和控制生命周期。工具返回 `accepted/executing`、HTTP 提前返回均不能释放搜索控制权，也不能触发 `graph.py` 收尾逻辑提前恢复空闲自由探索。
- 当前通用 runner 的 `max_turns=12 / max_effects=6` 不能直接成为空间搜索的隐式上限。搜索子图使用明确的任务总预算和每步期限，不提高所有智能体的全局预算，也不通过递归提交新任务绕过限制。
- 每步运动必须有可核对的执行 ID 和实际反馈；恢复任务时先重读设备状态、地图代次和账本，不重发未确认是否执行过的运动。
- 开始搜索先观察当前位置，目标已经在眼前时直接进入确认；任务恢复、转向或导航完成后使用新的停稳图像，不用运动前缓存帧更新覆盖。
- 自由探索使用相同工作流，由现有动机图按许可启动有界探索段；指定搜索持续推进直到明确结果或预算结束，不再每隔若干空闲 tick 才走一步。
- 用户遥控、急停、休息、断连和控制租约变化通过现有取消链传播到当前子图及 Navigator。停止后不自动重放目标。
- 断链时只能确认服务端已停止发送，不能由此推断机身停稳。停止命令未送达或缺少新鲜反馈时返回 `stop_unconfirmed`；当前固件的断流停车行为必须在现场验证。
- 初次接线前列出管家派发、工具超时、Go2 任务期限、导航期限之间的关系，统一沿用一个任务 ID；后台任务提交成功只能显示“执行中”。

### 4.6 识别、定位与到达

- 复用当前视觉模型，优先在停稳的观察点推理，避免每个控制周期都调用模型。
- 检测返回明确的未发现／疑似／确认及图像证据。需要至少跨不同帧确认候选；重复使用同一帧不算复核。
- 首先实测当前视频尺寸对应的相机内参、畸变和安装关系。默认站立姿态下，地面接触点投影作为地面目标位置估计，雷达点聚类用于交叉验证；目标被遮挡、接触点不明或数据矛盾时，不伪造精确坐标。
- 点云关联按采集位姿和时间检查，不再只取 bbox 中全部高于地面的点的中位数。过期／配对不可靠的样本重采集。
- 为目标选择满足机身空间和目标避让的停靠点，朝向目标；继续使用同一 Navigator 执行，禁止视觉工具绕过导航器直接持续给速度。
- 到达需要新鲜位姿接近停靠点、实际停稳、重新看到相同目标且距离符合约定。图像变大、模型说“到了”、命令已接受均不够。
- “已发现”可以先报告；只有接近和复核完成才报告“已到附近”。接近失败要保留已发现的照片与失败原因。
- 停靠距离在地面目标试验中固定：按机身前缘到物品边界计算，不直接把机身中心距离当净空。先记录几次实测误差再冻结验收容差。

## 5. 实施阶段与退出条件

所有阶段先离线验证，再进入相应现场测试。每个阶段拆成小改动，单次能通过回放或 PWA 看见结果；不要一次重写所有文件。

- [ ] 记录导航／搜索各阶段原因、地图年龄、有效样本数、路径长度、实际位移。
- [ ] 录制同位置“障碍存在 → 移走 → 重新观察”的序列，确定当前体素流能提供哪些清障正向证据；缺乏证据的区域只能待复核，不能靠超时直接变自由。
- [ ] 运行相关现有测试并记录实际基线，区分已有失败与本次回归；旧计划中的通过数不能作为当前基线。

退出条件：不连接机器狗也能重放地图与选点，稳定复现已知失败机制。录制／回放默认不发送任何动作。

### P1 同会话地图和观测证据

- [ ] 实现 `session_map.py`，接入 sensors 回调；使用只读快照供导航与探索访问。
- [ ] 融合多帧地面与障碍证据；保留最新局部障碍对全局规划的约束。
- [ ] 对转身失败输出实测障碍／证据不足明细，完成有限观测补全和转向扫掠检查。
- [ ] 会话变化、传感器过期、地图边界增长和内存上限有明确行为。

退出条件：走过的区域不会因离开当前雷达窗口而全部消失；新障碍及时出现；移走障碍在可靠新观测支持下清除，证据不足则标记待复核／未知并安排复看，不无限当作确定障碍，也不因为没点就误清；真实稀疏地面样本不再靠一帧决定长期行为。

### P2 重建探索选点与观察覆盖

- [ ] 迁移／改写 dimos frontier 聚类与评分核心，用 SSM 地图和坐标类型承载。
- [ ] 增加已知区域的观察点候选及朝向；首版不做房间语义图。
- [ ] 加入目标保持、有限失败重试和已观察区域去重。
- [ ] 接入 Navigator 的目标朝向与真实导航结果。
- [ ] 先运行只计算不执行的对照模式，在同一记录上显示旧／新目标、路径和原因；不保留永久双导航系统。
- [ ] 新选点回放通过后，删除被替代的旧筛选和无调用辅助代码；新测试集中到 `cloud/go2/tests/`。

退出条件：边界在 1.5 米之外仍能产生可达方案；无 frontier 的已知房间仍有合理观察任务；轻微朝向扰动不会造成无解释的频繁切换；不能转身时能提出有证据支持的恢复方案或明确停止原因。

### P3 单房间自由探索与找物闭环

- [ ] 建立 `search.py` LangGraph 工作流，复用动机图、执行上下文、任务注册表和动作账本。
- [ ] 给公开工具增加 `go2_find_object(target)`，沿用现有任务查询与取消入口；内部阶段不扩展成大量对外工具。
- [ ] 找物任务接入观察覆盖、候选确认、位置估计、停靠与复核。
- [ ] 修正图像定位参数与数据配对；旧可见目标工具继续是单次接近能力，不靠删除 terminal 配置实现无界搜索。
- [ ] 处理时间／路程／步数预算、目标不存在、目标不可达、用户中断和断线。
- [ ] 现有活动流显示“正在搜索／发现候选／已确认／正在靠近／完成或未完成原因”，并显示照片；地图页面需要时加当前路径和观察点，不另建管理后台。
- [ ] 完成视觉接近执行器收敛、工具文件瘦身、旧 Drive 决策删除、调用方与测试迁移；检查没有残留第二条自主搜索／接近执行链。

退出条件：地面物品放在初始视野外，机器人能自主换观察方向或位置，发现、报告并走到附近；物品不存在时有界结束，不虚报发现或完成；自由探索会增加有效观察而不是无限原地／重复巡游。

### P4 单房间验收与定位问题检查

- [ ] 在用户指定的单房间或有限空间内，完成初始视野外目标的发现、报告、接近和复核。
- [ ] 验证无目标、路径暂时受阻和用户中断时的行为，记录范围内尚未检查的区域。
- [ ] 结合上述试次检查定位与到位误差；若出现明显地图重影或路径偏离，再用录制数据分析原因。
- [ ] 单空间验收通过即保留轻量方案；仅在确认地图漂移是失败原因且需要回环校正时进入 P4b。
- [ ] 逐项关闭保留／迁移／删除清单；清除临时开关、重复配置、无用依赖和失效入口，完成受影响模块回归。

退出条件：完成第 7 节单房间验收，满足指定范围内的找物与接近目标。失败按实际原因修正，不因缺少更大范围测试而阻止交付。

### P4b 必要时迁移回环校正

- [ ] 先在录制数据上验证最新 dimos 的关键帧、ICP 与 PGO 核心，比较同一批数据的误差和耗时。
- [ ] 检查 GTSAM／点云依赖在当前环境的可安装性和 Python 3.13 兼容性；上游包声明低于 3.13，不等于算法无法移植，但不能未经验证直接引入整包。
- [ ] 优先迁移纯算法与最小数据类型到现有目录；不复制 dimos 的启动、连接、Agent、LCM 和 GUI。
- [ ] 只有依赖确实无法在现有进程兼容、且回环是实测必要条件时，才采用一个专用计算子进程；这是明确的成本升级项，不是首版预设架构。
- [ ] 地图校正时同步处理观察记录、目标候选、命名位置与在途路径，或使其失效后重新观测；禁止只移动地图却保留旧目标坐标。
- [ ] 重新运行原先失败的单房间场景及相关回归测试。

退出条件：定位升级真实解决指定空间内已复现的问题；代价不超过服务器可承担的接收与规划预算，运动入口仍唯一。

## 7. 测试与最终验收

### 离线回归

在现有 `cloud/go2/tests/` 和 `cloud/agents/go2/tests/` 增加具体行为测试，优先使用真实记录和少量可解释的合成场景：

| 场景 | 必须满足的结果 |
|---|---|
| 边界仅在 1.5 米之外 | 能找到可达观察方案，执行距离仍受局部安全约束 |
| 地图已知但相机只看过前方 | 继续安排新的观察朝向／位置 |
| 地面有小缺口但无实测障碍 | 能解释可信度与恢复选择，不直接永久卡住 |
| 真实障碍位于转向扫掠范围 | 仍阻止碰撞，不能靠缺口补全把障碍抹掉 |
| 朝向轻微变化、地图局部噪声 | 目标选择稳定；切换有可记录的理由 |
| 新障碍、障碍移走、地图窗口移动 | 局部实时响应、历史覆盖保留、清除依据正确 |
| 图像／位姿／雷达过期或错会话 | 不产生可信目标坐标，不执行依赖运动 |
| bbox 混入地板／背景 | 不把背景中位数当成目标，不虚报接近成功 |
| 无目标、所有观察点受阻、预算耗尽 | 分别给出准确结果与未检查区域 |
| 取消、重连、恢复、重复提交 | 无动作重放，无旧目标继续执行，无租约冲突 |
| 长任务返回执行中、原用户凭据到期 | 不提前恢复自由探索，不丢失任务归属，不延长运动授权 |

### 现场分步验证

1. **静止观察**：检查图像、相机参数、目标识别和定位误差，输出照片及投影证据。
2. **短程导航**：验证前进、转向、绕障、停止和目标朝向。开始前确定停靠净空与误差容差，不使用摇杆值代替实测速度。另在限定低速和可立即接管的条件下测当前固件的速度命令保持时间、断流后的实际停止行为和距离；软件取消不能替代机身停车证据。
3. **单房间搜索**：目标分别位于初始视野外、家具旁及需换视角的位置；加入一次无目标试验。
4. **受阻与中断**：在同一测试空间内检查路径暂时受阻和用户中断后的行为。

仅当上述试次出现定位问题时，额外回放轨迹并比较地标、墙面重影和导航误差，判断是否需要 P4b；不另设跨房间或长路线测试门槛。

完整成功试次必须包含“自主发现目标、报告图像证据、走到附近、实际停稳并重新确认”。至少三个不同目标布置连续通过；记录失败试次，不只保留成功录像。这是首版验收门槛，不等于长期成功率保证。

无目标试次不能虚报发现；受阻试次必须保留未检查区域；停止／取消试次不能在任务结束后继续发速度。现场测试有用户可立即接管，并限定明确的测试区域和运动范围；本计划编写本身不启动运动测试。

### 性能与费用

- 记录传感器接收间隔、地图构建时间、规划时间、控制周期、VLM 次数和整次任务耗时。
- 云服务器当前资源需在实施开始时确认。上游新版 PGO 地图存在 CPU 路径，不能直接以“必须买 GPU”作为前提；是否可用由回放耗时决定。
- 对比改造前后的相同录制数据，确认地图／模型工作没有造成遥测或控制饥饿。
- VLM 优先在停稳观察和候选确认时调用；优先复用图像观测，禁止对同一帧重复付费推理来假装多帧确认。
- 达不到实时要求时先降低非控制工作的频率、合并重复计算、限制候选数量；不能通过放宽过期数据运动门禁掩盖性能不足。

## 8. 上线、回退与完成判定

- 每阶段保留可回放证据和改动前后结果。只在确有接口冲突时新增字段／端点，避免提前建设通用协议。
- 新探索工作流接入期间用一个临时启用开关切换，不能让新旧策略同时控制机器狗；验收后删除被替代的旧分支及临时对照代码。
- 首版默认仍为 manual。用户开启自由探索或明确提交找物任务后才运行对应工作流。
- 上线前同步公开工具、Card、权限、任务超时和 SSE 展示；保留现有动作与生活状态契约。
- 旧代码清理和目录职责收敛是交付门槛：不得以功能已跑通为由遗留重复执行器、废弃工具主体或散落测试；不得通过删除有效回归测试掩盖行为退化。
- 发生回归时停止搜索任务并回到 manual，保留遥控和现有稳定动作；不恢复已判定不可靠的自主运动。
- 完成判定：P0～P4 的单房间目标验收通过；若确有必要触发 P4b，则完成对应修复；所有实机限制和未检查区域有记录。完成指定空间内的找物与接近实测即可交付。
