# Go2 单房间探索／找物实施记录

日期：2026-11-07。对应 [原计划](2026-11-07-go2-minimal-exploration-object-search.md)。

状态：软件改造与离线验证已实施，现场验收尚未执行。用户确认没有预先准备的范围／标定文件，将在软件检查后开机，再协助完成静止检查、范围确认和测距标定。不能把这份记录视为 P0～P4 全部验收通过。

## 已实施的代码

- `SessionMap` 在同一 odom 会话内累积地面与障碍；接收端一个工作项加一个可替换待处理项；计算在接收锁外，最终核对会话代次后发布不可写数组快照。限制单帧和累积地图格数，拒绝不同坐标格网。
- 全图可达搜索、边界聚类、相机观察覆盖与候选朝向；移除旧的距离／方向筛选执行器。诊断复用同一个可达搜索。障碍与地面证据冲突产生复看候选，不凭缺点或时间清除障碍。
- 转向按实际角度的机身扫掠检查；区分障碍、地面不足与地图范围不足。Navigator 使用新鲜地图快照、目标朝向和原控制租约。
- 一个 LangGraph 搜索子图支持 `explore` / `find_object`，从当前位置观察开始，跨帧确认、选点、导航、接近、到位复核。有限几何失败可换点；失权、断链、过期与取消不重试运动。探索段保留同定位会话的有界观察覆盖。
- `go2_find_object(target)` 明确 `motion=True`，admin/visitor 均可在原会话授权内提交；不要求打开永久探索。Card、管家派发、API 命令和 SSE 进度已接通。动作先写共享账本，重复／恢复任务不盲目重发。
- 视觉测量集中在 perception，唯一接近执行器为 `navigation/target_approach.py`。旧 `visual_approach.py` / `visual_lidar_navigate.py` 删除，诊断、同伴游戏和有效测试迁移。游戏不能跳过最终视觉复核。
- 必须有对应机器狗、分辨率、站姿的实测标定；没有标定可发现和报告目标，接近明确返回 `calibration_unavailable`。目标接触点与局部雷达簇交叉核对，不使用 bbox 内全部背景点的中位数。
- 搜索进度、照片和停止入口沿用现有活动流。访客照片只存有界内存，15 分钟过期；停止走带 CSRF 的用户命令网关，服务端以新鲜位姿确认停稳。
- 耗时业务计算复用 `cloud/agents/common/runner.py` 的 `invoke_blocking`，不阻塞接收和控制。小型 Graph 路由直接异步执行。

## 范围和期限

2026-11-09 按用户要求移除人为活动范围／搜索边界限制：自由探索和找物都从当前实时地图的可达区域选择观察点；自由探索优先寻找地图边界，不需要额外设置矩形范围。地图扩大时重新计算可达点，定位会话变化时结束旧任务，保留障碍、机身通行空间、控制租约和停稳校验。手工范围配置接口、命令与旧环境配置入口已移除。

| 层级 | 期限与归属 |
|---|---|
| 管家 | 原总预算 180 秒保持不变；下游受剩余父预算约束 |
| 搜索子图 | 最长 240 秒、20 次导航、20 米实际路程；探索段最长 60 秒 |
| 工具 | 250 秒，为搜索退出留余量 |
| Go2 服务端任务 | 显式找物默认 270 秒；同一任务 ID 持续托管至终态 |
| HTTP | 短同步窗口后返回 executing；任务继续存在，可查询／取消 |
| Navigator | 单次导航 60 秒；当前用户凭据、任务期限更早到期时立即退出 |

所有期限取原用户授权／父任务期限的更早值；不使用 SYSTEM_CONTEXT 延长用户授权，不提高所有智能体的全局轮数预算。

## 开机后的验收顺序

1. 用户开机并在现场可接管；先保持 manual，检查连接、图像、odom／雷达新鲜度与当前定位会话。仅静止观察和录制。
2. 依据实际房间布局确认一个无台阶、无出入口穿越的小范围，设置当前会话边界。无需用户提供文件。
3. 在相同视频尺寸和站姿下采集标定图、实测地面位置／距离，检查相机内参、畸变、安装关系和投影误差，生成并复核标定文件。不能把猜测参数或虚假的 verified 标志当成标定。
4. 验证短程直行、转向、绕障、停止以及当前固件断流停车距离。通过后再试初始视野外找物、无目标、受阻与用户中断。
5. 三个不同目标摆放连续完成“发现、照片报告、接近、停稳并再次确认”才关闭最终验收项；记录失败试次和未检查区域。

现场录制工具只读取已连接设备，不自动连接、不执行动作、不调用视觉模型：

```bash
UV_CACHE_DIR=/tmp/ssm-uv-cache uv run --no-sync python scripts/record_go2_navigation.py --seconds 10
```

输出保存至 `logs/go2-search/recording_<id>/`，包含 odom、完整体素样本、视频索引和动作状态观测；原始命令／回执继续关联现有 session JSONL。采样器报告序号缺口、写入丢帧与字节上限，存在缺口时不得称为完整接收序列。需要在现场录制“障碍存在→移走→重新观察”的连续序列。

## 对照 dimos 与历史成功链路后的修复

用户要求参考 dimos 和此前成功方案，取消“必须先提供本机标定文件才能进行任何接近”的实现限制。保留实测标定的地面投影路径，并增加独立的真实 LiDAR 点簇定位路径；不生成虚假的 measured/verified 标记。

- dimos 源码对照固定 commit `3645017c7ace59badd938283b30439a83545fcd7`：`dimos/robot/unitree/go2/front_camera_720.yaml` 为默认相机模型，`dimos/perception/detection/type/detection3d/pointcloud.py` 将点云变换并投影到图像。采用该 profile 的 equidistant 畸变模型，640×360 使用同视场缩放假设，结果明确标记 `upstream_model_not_per_robot_calibration`。该模型用于关联像素，物体距离必须来自真实点云。
- 历史日志 `session-peer_0495a856c6914c06b9c6e51a5974bccb.jsonl` 曾以25个物体点导航至白色地面猫头鹰附近；但当时游戏路径跳过最终视觉确认，因此只能证明曾移动并停靠，不能作为完整到位精度验收。
- 新 `locate_lidar_target()` 在模型调用前配对 RGB、位姿与点云，过滤地面、检查整簇空间范围、拒绝背景切片和多簇歧义；检测后再次检查位姿稳定性。距离没有证据时不使用任意单目距离。
- 缺少物体回波时，现有 Navigator 可执行最多3次、每次0.30 m的观察位置调整；全段机身及终点之外仍须有可通行地图证据，速度0.15 m/s。换视角动作本身不构成找到/到达证据。
