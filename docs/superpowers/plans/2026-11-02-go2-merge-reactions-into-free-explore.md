# Go2 统一自主循环与 reactive 并入自由探索实施计划

> 日期：2026-11-02  
> 状态：待实施；本文只规划，不修改运行代码或启动机器狗  
> 范围：Go2 自主决策、信息接入、任务交接、视觉与导航协同、同伴消息；灯智能体的 `reactive` 模式不变

## 1. 目标与边界

Go2 只保留 `manual` 和 `free_explore` 两种自主模式。`manual` 不因视觉或同伴消息自发行动；`free_explore` 是一个持续的智能循环：

**探索一个安全的地图边界步骤 → 汇总视觉、位置、设备状态及同伴消息 → 决定下一步 → 调用一个工具并等待真实回执 → 更新任务状态 → 继续探索或处理当前任务。**

沿局部地图 frontier 探索仍是默认行为。人、脸、主人身份、灯的邀请和今后的新观察只是这个循环的不同输入，不分别启动独立的运动流程，也不意味着每个事件都要打断导航或执行动作。Go2 可选择忽略、回复、延后、请求更多信息或接受任务。接受任务后才交接运动控制；任务结束后基于新的 odom 与地图继续探索。

本次移除 Go2 独立的 `reactive` 模式和两个专用实现文件。保留现有 Navigator、局部栅格、frontier、工具安全校验、控制租约、LangChain/LangGraph 运行器、Agent Card 和 MQTT 同伴通信协议。不要新建第二套 Agent 循环或导航器。

## 2. 已有能力与真正缺口

| 当前实现 | 已有能力 | 缺口 |
| --- | --- | --- |
| `cloud/agents/go2/workflows/free_explore.py` | LangGraph 动机 tick 判断是否探索或检查附近的人 | Graph 不管理当前任务、外部消息与工具结果；不能代表完整的自主循环 |
| `cloud/go2/mode/free_explore.py` | `Drive` 选择 frontier、一次最多连续导航 15 个目标、到达后视觉描述和社交检查 | `_run_loop()` 等待 `_do_explore()`；消息无法在导航中进入统一决策，社交分支也局限于人 |
| `cloud/peers/inbound.py` → `cloud/agents/go2/graph.py` | 已验证的灯/其他同伴消息可触发 Go2 逐步工具调用 Graph | 消息在独立 worker 中执行，与 `Drive` 没有任务交接；可能因不同 session 的控制租约冲突 |
| `cloud/space/context.py`、`cloud/go2/space_context.py` | 可读取同空间设备状态、约束、发现和公开技能；灯状态含 RGB 时可取颜色 | 需在决策前检查新鲜度、来源和活动范围，不能仅相信邀请文字中的颜色 |
| `cloud/go2/tools/tools.py`、`cloud/go2/perception/vision.py` | `go2_observe` 可用视觉模型描述当前帧；现有快速检测主要给人/脸结构化信息 | 尚无可靠的“物品类别＋颜色＋框＋置信度＋连续跟踪＋地图位置”结果，不能把一段视觉描述当成物品已定位 |
| `cloud/go2/mode/reactive.py`、`cloud/agents/go2/workflows/reactive.py` | 身份、去重、冷却、教导匹配和单动作 Graph | 有价值的约束需迁入通用自主流程，然后删除两个文件 |

`run_go2_loop` 与共享 `run_role_graph` 已提供“模型选一个工具→执行→观察结果”的 LangGraph 能力，但单次运行有轮次、动作次数和期限上限。不要把永不结束的探索塞进一次对话运行；由自由探索的 LangGraph 保存当前任务与检查点，按有界回合复用共享运行器和工具执行边界。

## 3. 目标架构：一个自主流程，多种信息来源

`Drive` 只负责 Go2 自主模式的生命周期、线程安全唤醒、设备回调接入和执行适配。扩展现有 `free_explore` LangGraph，使其掌管**当前目标、待处理信息、任务切换和下一步工具决策**。一次只允许一个 Go2 自主动作进入有副作用的执行边界。

```text
视觉/身份变化 ─┐
灯/管家/其他同伴消息 ─┼→ 有界事件入口 → 读取实时空间与设备状态
用户任务、活动变化 ─┘                         ↓
                                  Go2 自由探索 LangGraph
                         继续 frontier / 回复 / 接受任务 / 查询 / 调工具
                                                   ↓
                            现有工具执行器 + Navigator + 控制租约
                                                   ↓
                                      真实回执 → 下一次决策
```

### 3.1 信息入口与上下文

- 统一输入为有界事实：`event_id`、`source`、`kind`、`ts`、`deadline`、`activity_id`、`message_id`、观察字段和必要引用。用原消息 ID/帧 ID 去重，拒绝过期、重复、跨活动及来源不可信的输入；摄像头帧和整张栅格不写入 Graph 检查点。
- 视觉回调记录变化和候选观察，不在视频回调中调用模型或运动工具。地图、odom、灯的 RGB/亮度、同伴在线状态、用户约束等在决策时通过现有实时快照读取，并带新鲜度；缺失值保持 unknown。
- 同伴消息通过现有签名验证和空间成员检查后进入 Go2 自主入口。消息正文是协作提议，不授予运动权限；外部文本不能直接覆盖用户任务、安全条件或工具白名单。`manual` 下不能因邀请自动开始游戏。
- 新增事件类型时接入相同入口和 Card/教导观察契约，不为每种事件增加一种运行模式或一条后台运动任务。

### 3.2 任务选择与执行

- LangGraph 状态只保留当前目标、来源/关联消息、截止时间、任务阶段、待处理事件 ID、最近工具结果、探索进度、模式代次和必要冷却。`Drive` 不保留另一套独立的任务决策状态。
- 优先顺序由硬安全门先约束：急停、断连、用户接管、活动失效和控制租约优先；在可行动范围内由 Go2 Graph 决定是否处理新邀请、继续已接受任务或继续 frontier。普通人脸变化或设备状态变化默认只更新上下文，是否值得切换任务由决策结果确定。
- **已启用的可执行教导属于条件动作约束**：当新鲜观察命中 Card 校验过的绑定，且动作在自主技能白名单内时，Graph 应把它排入待执行任务；人格可决定招呼的措辞，不能随意把“看到主人就打招呼”的有效命中当成可忽略的社交建议。安全门、冷却、同一身份重复事件和更高优先级用户任务仍可阻止或延后动作，并记录原因。仅有自然语言教导、未启用绑定或普通人脸检测均不触发主人规则。
- 将长探索拆成可让位的**一个 frontier 步骤**。导航期间可收到新事件并唤醒仲裁，但仅在决定切换任务或出现安全中断时，才取消当前会话拥有的导航并确认停稳。停稳未确认则不下发下一项运动，也不宣称任务已开始执行。
- 主人招呼的具体路径是：身份服务确认 `role=owner` 且是新识别事件 → 以 `vision.owner_recognized` 匹配已启用的 `go2_sport(Hello)` 绑定 → 暂停当前导航并确认停稳 → 若主人仍在可用观察范围且规则未过期，执行一次 `Hello` → 根据真实回执回复 → 读取新地图继续探索。匹配在观察到达时完成并保存有限期任务；停稳后重新检查身份和有效期，避免直接拿几秒前的旧帧动作。
- 接受新任务后，以当前 Go2 自主控制会话持有运动权；同伴消息 ID 只作为来源和回执关联，不另建与探索争用租约的运动会话。后续工具调用通过现有 `execute_tool()`、FSM、地图校验、租约、效果账本和检查点；每步结果进入下一轮决策。读取信息和生成回复可以并行，但有副作用的 Go2 动作必须串行。
- 完成、拒绝、超时或取消后，任务状态明确收束；自由探索重新读取新鲜 odom 与局部栅格选择 frontier，不复用中断前的路径。任务有期限和步数预算，避免游戏一直占据探索；用户接管后不自行恢复。

### 3.3 消息与完成语义

- `cloud/peers/inbound.py` 对 Go2 自主邀请改为“校验后投递任务并返回”，不能让 MQTT worker 等待整场游戏。投递成功只是收到消息；Graph 作出接受/拒绝决定后再发对应答复。
- 接受时关联稳定 task ID，并用现有 `send_progress` 报告开始；只有实际任务完成、失败或取消时才用 `send_result` 给最终结果。`accepted`、`executing`、`timeout` 和视觉候选都不能当作 `ok`。重复消息、服务重启或超期不能重放运动命令。
- 现有同伴回复防无限对话规则保留：回复可进入上下文，但不能因一条确认回复再次启动相同任务。兼顾现有消息最长有效期；超期任务按原关联 ID 收束或报告 unknown，不无期限运行。

## 4. “灯邀请找同色物品”作为端到端验收场景

1. **邀请到达**：Go2 正在 frontier 导航；灯经现有同伴消息提出游戏。消息进入待处理队列，`Drive` 不立即让第二条对话任务控制运动。
2. **理解与核实**：Go2 决定是否参与，并读取同空间灯的当前 RGB/颜色及状态时间。颜色不可用或过期时先询问/拒绝，不能把灯消息文本当作实时灯色。接受时固定本轮目标颜色及其来源时间；灯后来变色需要重新协商，避免搜索目标悄悄变化。
3. **安全交接**：决定接受后暂停属于探索会话的当前导航，确认停稳，建立有期限的游戏任务，再回复“接受”。若停稳无法确认，游戏保持 blocked/unknown，不执行游戏运动。
4. **找物品**：保持地图边界探索机制，每到一个安全观察点调用视觉工具寻找目标颜色的物品。视觉模型的自然语言描述只能形成候选；若要声称“找到了某物”，需可复核的结构化物体/颜色证据、连续观察和当前画面引用。找不到时继续下一 frontier，至预算/期限耗尽后如实报告。
5. **结果与恢复**：把找到的候选、证据或失败原因反馈给灯和用户；结果以真实观察为依据。游戏结束后读取新地图与位置继续探索。**导航到物品旁边**是下一层能力：需要物体像素位置到机器人相对位置/局部地图目标的转换、跟踪与接近复核；本计划不把单帧描述误作可导航坐标。

这个场景只用于验证通用流程。换成“灯请狗问候主人”或其他智能体发起的任务，仍走相同的事件、仲裁、工具、回执和恢复路径。若是用户预设的“看到主人就打招呼”，有效的主人身份观察命中规则后应主动安排招呼，不需要灯再发邀请。

## 5. 按可验证粒度实施

### 阶段 A：建立统一入口与可让位的探索步骤

- 在 Go2 API 进程内建立有界、线程安全的自主事件入口；视觉/身份回调、活动/空间状态变化和同伴消息只发布事实。将 worker 线程投递安全地交给 `Drive` 所在事件循环；模式代次切换后旧事件失效。
- 把 `_do_explore()` 的连续 15 步交给 Graph 逐步驱动：frontier 选择、A*、Navigator 与占据栅格算法保持原样，每步结束后重新汇总上下文。导航中的新任务可唤醒仲裁；暂停只停止本会话运动并等待停稳。
- 验收：灯在狗导航时发消息，探索不会与消息处理同时下发运动；忽略/延后邀请时不发生不必要的急停；用户急停和断连可立即阻止后续动作。

### 阶段 B：扩展 LangGraph 为任务仲裁与逐步工具循环

- 在 `cloud/agents/go2/workflows/free_explore.py` 扩展当前动机 Graph，增加上下文汇总、目标选择、任务阶段、工具结果回写和恢复分支；复用 `cloud/agents/common/runner.py` 的逐步工具调用、检查点与效果账本。`Drive` 退回设备侧适配和唤醒，不另写自研模型解析/任务循环。
- 现有 Go2 对话 Graph 继续服务明确用户任务；同伴自主邀请交给统一自主 Graph。复用已有限时工具执行能力，长任务分成有界回合，不把单次 `run_go2_loop` 的限制当成无限自主运行时。
- 将 `cloud/agents/go2/workflows/social.py` 的同伴联系决策和现有空闲社交动作接入统一仲裁；不能再由 `Drive` 的独立社交计时分支绕过任务状态。教导候选仍由 `teaching_bindings.candidates()` 按 Card、观察和有效期校验；命中的可执行教导生成有期限的待执行任务，并在动作前重查身份、冷却和安全条件。人格影响表达，安全门和真实回执不交给模型自行保证。
- 验收：视觉、灯消息、管家消息和环境变化都能成为同一 Graph 的输入；一个任务最多有一条生效的 Go2 运动链；失败/超时不会被当成成功，结束后探索可恢复。

### 阶段 C：迁移 reactive 并删除专用文件

- 从 `cloud/go2/mode/reactive.py` 迁入通用事件去重、身份确认、教导匹配和冷却；`vision.owner_recognized` 仍只由身份服务确认，`face_presence` 不可冒充。把 `cloud/agents/go2/workflows/reactive.py` 中仍需的候选动作及回复约束归并到统一工具决策与共享回复流程，确保现有自由探索对它的导入先替换。
- 删除 `cloud/go2/mode/reactive.py` 与 `cloud/agents/go2/workflows/reactive.py`，不留兼容壳或第二个自主后台任务；清理 `reactive_action_candidates()` 及 Go2 专属 reactive 提示词中失效的分支。
- `cloud/go2/router.py` 清理 `reactive_mind`、视觉回调和模式切换；`cloud/go2/card.py`、相关 PWA 文案与 Go2 API 只提供 `manual/free_explore`。旧 `reactive` 值返回明确的 400；`/mind/last_decision` 改为统一任务决策诊断或移除。
- 验收：原两个文件已删除、无 Go2 reactive 导入；人/脸/主人教导仍可按观察契约生效；灯智能体的 `reactive` 代码及历史文档不误删。

### 阶段 D：找物品场景与视觉能力验收

- 用现有 `get_space_context()` 获取灯的最新 RGB，提供“查目标颜色”和“观察画面找匹配物品”的受限任务步骤。若现有 `go2_observe` 只返回描述，先将结果标为候选；补充结构化物体/颜色证据与跨帧确认后才允许输出“找到”。
- 先完成“在安全探索点发现并报告”闭环；若毕业设计要求走到物品旁，再单独补物体定位到 odom/局部栅格、目标跟踪和安全接近，不以视觉像素直接调用坐标导航。
- 验收：灯色过期、物品颜色不确定、物品离开画面、地图不可用、游戏到期都能如实结束；找到物品时能追溯灯色快照、画面证据和任务回执。

## 6. 验证矩阵与完成定义

先用模拟消息、录制视频帧、导航回执和空间快照验证，再在可人工接管的开阔区域进行短距离真机验证。每一阶段分别检查 Go2 当前任务、导航状态、消息关联 ID、工具回执和恢复后的地图目标。

| 场景 | 预期结果 |
| --- | --- |
| `manual` 收到灯邀请或看到人 | 可显示/记录消息与观察，不启动自主任务或运动 |
| `free_explore` 导航中收到普通状态变化 | 更新上下文；Graph 可继续当前 frontier，不强制停机 |
| `free_explore` 导航中接受灯的游戏邀请 | 原导航先安全让位；同一自主运动会话执行游戏；不出现控制租约争用 |
| 灯颜色未知、过期或游戏中变化 | 查询或协商，不按未经核实的颜色搜索或宣称找到 |
| 视觉只给自然语言候选 | 保持“疑似”；没有结构化证据时不报告已找到 |
| 人/脸抖动、主人身份未确认 | 去重、冷却；`face_presence` 不触发 `vision.owner_recognized` 教导 |
| 导航中确认主人，且启用了“看到主人就打招呼”绑定 | 在规则仍有效且安全可停稳时暂停探索，执行一次 `Hello`，按回执回复，再重新规划 frontier；不因模型偏好跳过 |
| 主人离开、身份失效、规则未启用或停稳失败 | 不执行招呼；记录过期、未命中或安全阻断原因，不用旧画面补做动作 |
| 邀请重复、活动结束、任务超期、重启 | 不重复执行动作，任务有明确终态或 unknown |
| 用户急停、控制权转移、断连、停稳未知 | 不下发后续运动，不自动恢复，不声称任务完成 |
| 游戏完成或拒绝 | 从新的 odom 和局部地图恢复 frontier 探索 |

完成定义：Go2 只有 `manual/free_explore` 两种自主模式；视觉、空间状态和同伴消息由同一自由探索任务流程仲裁；frontier 仍是默认探索策略；有副作用工具串行且以真实回执更新任务；两个 Go2 `reactive.py` 已删除；灯的 `reactive` 保留。
