# SSM Agent Card v1

SSM Card 是 MQTT retained 控制面的能力声明。`ssm/agents/{unit_id}/card` 发布自描述卡；ESP32 的 `manifest` 由云端 builder 转成相同格式。卡片借鉴 A2A 的身份和技能分层，但 MQTT 和普通 HTTP 端点不是 A2A `supportedInterfaces`，SSM 当前不提供 A2A 协议服务。

## 版本与运行时

- `card_schema_version` 必填且为整数 `1`。未知版本不覆盖 Registry 中上一张有效卡。缺少该字段、旧 v0 卡和旧平面状态机均拒绝，不再做历史格式适配。
- `version` 必填非空字符串，表示智能体或固件版本。它不控制 Card 解析规则。
- 原始 Card 只含静态声明，不含 `online`、`state` 或 `training_capabilities`。Registry 分别保存 Card、MQTT status/LWT 和 state；`/api/devices` 与设备 SSE 在读取时合成实时快照。Go2 的快照 `online` 表示服务可达，`state.connected` 表示 WebRTC 控制连接。
- 顶层必填：`unit_id`、`device_id`、`name`、`description`、`agent_type`、`transport`、`skills`。ID 和文本字段均为非空字符串，`skills` 可为空数组。`tags`、`services`、`state_machine`、`modes`、`telemetry`、`widgets`、`suggestions` 可省略，消费者按空集合处理。

## 通信与技能

`transport.kind` 为 `mqtt` 或 `http`。MQTT 需要 `task_topic`；HTTP 需要同源 `/api/` 开头的 `endpoint`，可声明 `command_endpoint` 与 `state_stream`。卡片中供 PWA 请求的 URL 必须是同源 `/api/` 路径，不接受完整跨源 URL。它们只描述调用方式，不授予权限。

每个 skill 需要 `id`、`name`、`description`、`tags` 数组、`params_schema` 对象和 `invoke.action` 字符串。skill 用于发现能力，不意味着每个技能都在状态图中有按钮。

## 状态机

有状态机时需声明 `primary_region` 和非空的 `regions`；状态、转换、预览和布局只在区域内声明一次。区域的 `state_field` 是实时 payload 的字段名，例如灯的 `ism`、Go2 的 `body_state`。根层只放区域选择、连接、执行反馈、新鲜度和画布配置，不再保留 `state_field/states/transitions/views/layout/initial` 副本。没有状态快照时 UI 显示“状态待同步”。

每条转移的 `src`、`dst` 必须在 `states` 中，`trigger` 和 `label` 必填；`action` 为空或省略表示设备观测或任务事件驱动的自动转移，只展示，不派发命令。`safety=true` 走独立安全按钮。状态图显示全部节点及命令／自动事件关系，当前态与合法可请求出边重点显示；自环仍可作为操作入口，例如再次闪烁或关闭探索许可。`views` 可给状态和运行时占位态提供标签、说明和预览。支持 `light_ring`、`robot_pose`、`image`、`generic`；`image.src` 必须是同源绝对路径，未知类型拒绝 v1 卡，运行时缺少预览实现时显示文字。`layout` 可省略；声明坐标时应覆盖全部节点，消费者仍需根据节点数量避让，不能将部分固定坐标与另一种自动布局混排。

### 并行区域与统一页面契约

`regions` 是唯一状态机拓扑。每个区域使用相同的 `id`、`label`、`state_field`、`states`、`transitions`、`views` 结构；`parent:{region,state}` 表示激活前提，父级引用必须有效且无环。`retain_when_inactive=true` 表示父级未激活时仍展示最近观测，但不允许普通操作。灯可以只声明照明区域，Go2 可以声明连接、活动、生活和身体区域；共享 schema 不要求共享状态名或业务行为。不再接受或合成平面状态机。

状态机实时高亮统一以 MQTT 在线状态、Card 声明的设备连接（如有）和状态同步完成为前提。全局事件流断开或设备快照尚未重同步时，即使独立设备状态流仍连通，也不展示当前态、可达动作或执行高亮。独立状态流建立连接不代表状态有效，须收到通过 epoch/revision 合并校验的非空快照；退役连接与旧 revision 的迟到帧不能恢复高亮。离线或同步中保留拓扑、教导和最近观测供查看，以中性样式呈现，不将缓存显示成实时状态；主区域新鲜度明确为 `false` 时同样不高亮其最近观测，其他区域和独立停止入口仍按各自门禁处理。

- `state_machine.primary_region` 指向主区域，用于默认控件状态绑定和动作预览，不按 `body` 等固定名称判断设备。
- 区域可声明 `available_actions_field` 和 `blocked_actions_field`，分别绑定实时快照中的动作键列表和阻止原因字典。转移的 `availability_key` 默认取 `action`；例如 `action=LIFE` 的休息转移使用 `availability_key=request_rest`。
- `required_actor=admin|visitor` 是界面权限提示，服务端仍必须校验身份。`available_only=true` 表示只有实时可用列表包含该键时才展示次要入口，例如生活待命时的停止探索自环。其他不可用操作可以禁用并说明原因。
- `execution_field`、`last_execution_field` 指向实时快照中的当前请求和最近终态结果。请求包含 `command`、可选 `label`、`phase` 和关联 ID；终态还可包含 `result`、`confirmation` 和完成时间。它们不会将请求接受投影成物理姿态确认。
- 用户点击状态节点派发命令时，聊天区先插入该次操作的系统说明，收到回执后更新同一条说明，使先返回的自主过程也有操作上下文。只有成功回执携带对应目标状态事实时，才按 Card 的状态名称与说明反馈已进入该状态；仅发送、超时、失败或未知结果分别反馈原结果，不读取缓存快照推断完成。这不是角色发言，不新增模型调用，也不按相邻消息把后续过程归入该操作；状态高亮仍以实时状态流为准。
- `freshness_field` 指向主区域的实时布尔新鲜度字段；为 `false` 时该区域普通动作受限，旧观测可继续显示。Go2 的兼容字段 `body_telemetry_fresh` 表示反馈有效性，不设身体遥测有效期；未取得有效反馈、断连或明确电机故障时为 `false`。其他区域仍使用自己的动作门禁，不能因身体反馈无效禁用唤醒或停止探索。控制面 `online`、设备连接、新鲜度与动作完成是不同事实。
- 转移可用 `completion` 描述设备完成依据。`unavailable` 表示尚未具备可靠完成确认，图中有目标节点不代表该动作可以自动串联。当前 Card 的 `trigger_condition` 仅简述触发事件及必要条件，前端原样展示，例如“收到开灯指令。”；不重复源/目标状态，不附加执行过程、状态不变说明或“以实际反馈为准”等兜底话术。真实完成确为转换条件时直接写明，例如“收到坐下指令，设备确认已坐下。”，不能把接受指令写成姿态完成。该字段仅是展示说明，不参与执行门禁、稳定转换 ID 或能力哈希；旧卡缺少它时回退到 `event_label`，并保留单独声明的 `guard_label`，最后才回退到动作标签。多条真实事件分别展示，不合成一条无法辨认来源的条件。
- 可选 `state_machine.diagram={width,height,sections:[{label,top}]}` 定义白板尺寸、分隔线与小标题；区域的 `diagram_group`、`node_radius` 和归一化 `layout` 坐标决定可见节点的分组、大小和位置。这些展示字段不改变运行状态、动作参数或权限。Go2 通过 `diagram.media_position="left"` 在白板左上竖排小尺寸视频和地图缩略图，两者使用相同的 16:9 外框，内容等比容纳并可点击放大；休息、待命、互动、探索置于右上“行为”，姿态和动作置于下方；连接仍只在设备标题显示。未声明媒体位置的旧 Card 沿用顶部媒体行，避免新前端遮挡旧坐标中的节点。

Go2 的连接、任务开始／结束、运动开始／停稳和姿态恢复均声明自动边。身体命令边描述可请求的目标或动作阶段；实际状态高亮来自同一连接的真实观测和执行阶段，不由点击、RPC 接受或固定延时推断。

Go2 的 `states` 仅声明实际姿态和动作，不声明 `unknown` 或“姿态待确认”节点。没有可靠姿态时，快照中的 `body_state` 为 `null`；`body_confirmation`、新鲜度和动作账本继续决定可否执行。此时不高亮任何姿态节点，独立急停入口保持可用。

灯的主区域只有三个状态 `ism=OFF|ON|BLINKING`。新版 `fsm_version=3` 的“闪烁”默认 `count=0`，持续闪烁直到收到开灯、关灯或调色命令；边缘启动闪烁并上报 `BLINKING` 后返回 `ok`，表示已进入该状态，不等待自动结束。只有明确指定正整数次数时，才在闪完并确认恢复之前的常亮颜色或熄灭后，通过 `BLINK_DONE` 返回成功；旧 v1/v2 manifest 不再生成 Card。恢复硬件失败通过任务 `result=error` 和 `error` 字段报告，状态保留最后一次确认值，直到后续命令成功；不得增加异常状态。RGB、亮度、闪烁次数是参数，不扩展成额外状态。

灯的 `manual/reactive` 自主模式和用户让位窗口由云端维护，只通过实时快照附加 `autonomy_mode`、`control_state`、`control_hold_until` 和 `control_ts`，不再额外生成控制区域或复制照明状态机。`ON` / `BLINKING` 下的调色盘与亮度控件作为整体在可用区域水平居中，两者保持相同的垂直中心，窄屏使用一致的尺寸约束。

灯的云端字段通过 `/api/devices`、设备 API 与全局 `/api/events` SSE 的统一展示投影附加到 `state`。`control_ts` 是该投影自己的变化游标，控制事实不变时保持不变；每次配置、让位截止时间或到期状态改变时严格递增。消费者将物理 `ts` 与 `control_ts` 分别合并：新控制事件可复用旧物理时间，后续物理上报也不能清除较新的控制字段。`control_ts` 不刷新物理观测的新鲜度，`online` 仍由 MQTT status/LWT 决定；`ism`、RGB、亮度和原始 `ts` 仍来自边缘。该投影不会成为第二份物理状态存储或写入 `ssm/agents/{unit_id}/state`。

## Go2 人物与身份观察

Go2 的 `vision.person_presence`、`vision.face_presence`、`vision.owner_recognized` 和 `vision.stranger_recognized` 使用新鲜相机观察。
检测帧的 `ts` 为采集时间，`source_frame_id` / `camera_session_id` 标识原始帧与连接会话；
重复帧不产生新观察，超过 5 秒的观察不能证明当前有人或当前身份。
身份匹配分达到 80 且对应本地登记人员才返回 `recognized`；无匹配返回 `unknown`（陌生人），
无人脸、多脸、小脸、过期画面和服务错误不能作为陌生人或主人的证据。
身份结果的 `ts` / `frame_id` 指向实际用于匹配的检测帧，最多有效 5 秒；人脸框连续性不能替代身份复核。
临时服务故障不改变 Card 中配置性的身份能力声明，也不改变已确认教导的能力哈希；运行时错误由身份接口报告。

`vision.stranger_recognized` 的教导条件必须为 `where:{recognized:true}`，仅本次有效识别的 `unknown/stranger` 结果产生该事件。错误、禁用、搜索中、无人脸或多脸均不能作为陌生人证据；持续出现的同一张未匹配人脸不反复触发。

### 按教导动态观察物体

Card 固定声明通用 `vision.target_presence`，教导使用 `trigger:{event_id:"vision.target_presence",where:{target:"书本",detected:true}}`。`target` 为去除首尾空白的非空可见物体描述，最长 200 字符；书本、食物等是已确认教导的参数，不各自注册新事件或改变 Card。该能力不识别人物身份、所有权、不可见意图，不增加硬件或身体动作；身份条件继续使用可信身份观察。

观察适配从已确认、启用且与当前能力匹配的教导提取目标，合并同一目标，在现有相机采样入口异步批量观察。没有目标教导时不调用目标视觉模型；删除、禁用或修改教导后淘汰对应的旧观察。可见为 `true`，明确未见为 `false`，遮挡或判断失败为未知；未知不当作出现或离开。一次持续出现只产生一次触发，明确离开后再出现才能重触发。观察保留原帧标识与采集时间，5 秒后失效，推理完成不能刷新时间。重连、用户接管、新用户目标代次或规则版本变化后的迟到结果不得产生动作。

目标事实刷新与动作准入独立：原行为运行时仍可观察目标是否在场，每一步继续经过原 Go2 Graph、准确教导版本、真实姿态、控制租约和设备执行边界。忙碌时的新出现不排队等待补做。通用观察类型的首次增加会改变能力目录哈希，旧哈希教导保持失配并需要重新确认；不自动改写或启用已有运行数据。以后增加不同 `target` 参数不改变目录哈希。

物体教导共用既有约 1 秒相机采样入口，以本地 OpenCV 灰度差分判断是否需要语义分析。比较基线为上次成功分析的确切原帧，缩至 160×120、轻微模糊并抑制整体亮度偏移；像素亮度差大于 20、全局变化比例至少 5% 或局部 16×16 窗口变化比例至少 25%，连续两个不同采样确认后才作为变化信号。这些是软件初值，不能代替实机校准。局部变化不依赖人数增加，也不证明物体或身份。旧的 `VisionFrame.changed/change_type` 保留人数变化语义，继续供原人物／探索消费者使用。

教导物体模型请求的发起至少相隔 3 秒，同一观察通道只有一个在途请求，不积压旧画面；静态画面距离上次成功分析完成满 30 秒才兜底，新变化的成功分析会重置这段计时。新增或修改已启用教导、从暂停恢复时安排首检，但仍遵守限频；失败或超时后等待 10 秒再尝试。合法但结果不确定的分析可以更新调度计时和场景基线，不能提供执行依据；失败、旧代次、旧连接或过期响应不推进成功基线。全局默认参数为 `GO2_TRAINING_VISION_MIN_INTERVAL_S=3`、`GO2_TRAINING_VISION_FALLBACK_S=30`、`GO2_TRAINING_VISION_RETRY_S=10`，不逐条教导设置。

休息、断连、遥控、其他任务占用时暂停普通物体教导分析；没有有效物体教导时不请求模型。原教导执行期间，只有场景变化、正常兜底或原步骤确实需要新鲜证据时才分析，不因为某个长动作仍在执行就固定每 3 秒请求。需要刷新时，原 LangGraph 步骤最多等待 10 秒，并持续复核目标代次、连接、租约和教导归属；等待后重新读取教导版本、能力及身体状态再选择动作。保持原步骤及账本身份，旧事实不续期，失败的等待不由未来画面自动恢复动作。暂停和恢复不把未知当离开，也不重复执行持续在场的目标。

上述预算只控制教导后台物体观察。人脸身份专用服务、显式看画面、找物与自主任务观察保留各自现有入口和准入，不受这一路的 3 秒／30 秒预算控制；未将不同业务的视觉结果互相替代。

## Go2 相对移动

公开 `go2_move` / `MOVE` 技能使用 `direction`、`distance_m`、`angle_deg` 和可选 `speed`。前进、后退、左移、右移必须提供 `distance_m`（0.1–5 米）；原地左转、右转必须提供 `angle_deg`（5–180 度），两个目标参数互斥。`speed` 是平移速度或转向角速度上限，仅在用户明确要求速度时填写。平移默认 0.3 米/秒，按摇杆对应的 x/y 轴范围校验；转向默认及最大角速度与摇杆共用 z 轴声明（当前 0.8 弧度/秒），不再受平移默认值或独立导航转速上限压制。导航与相对转向共用 Sport Move 速度通道，原地转向按目标角度反馈停止；显式指定较低转速时按请求执行。删除移动的 `duration` 参数，旧定时请求拒绝，不用速度乘时间推测走距；LED 等其他技能的持续时间不变。

控制使用现有 Navigator 的速度循环、地图机身净空和停稳判定，相对目标不自动绕行。相对平移按请求速度执行至到量判定，不因短距离把整个运动阶段压到低速；地图路径跟随继续使用其路径速度控制。平移按初始方向上的里程计投影计算实际距离，默认到量容差 0.05 米；原地转角由朝向反馈计算。到量且停稳才返回 `ok`；受阻保留实际移动量和原因；停止未确认返回 `accepted/stop_unconfirmed`。任务超时只是上限，不是位移完成条件。Go2 最终回复经现有人格层表达，校验保留实测量、未完成的目标量和停车事实，不再承诺额外观察或移动；人格模型不可用或事实校验失败时才回退到原始实测说明。

导航后的目标复核可在有界窗口内等待新鲜站立遥测，随后仍需停稳画面与同一定位会话，不把里程计停稳直接写成站立。路径移动成功与目标复核失败分别保留，复核失败不能抹去已经确认的移动。货物视觉定位兼容只有一个对象的数组包装，多个对象、非对象内容及有歧义的目标仍拒绝；数量和目标框校验保持有效；货物地面接触处不可见不作为推物门禁。推物前进未达目标但停稳已确认时，反馈保留实际位移和停稳事实，货物移动仍须独立测量。

## Go2 推物测试与配送

配送通过可信父任务的 `search_request(..., require_cargo_measurement=True)` 要求现有找物 Graph 在完成前核对同一货物的新鲜视觉与位置。雷达关联有效时返回 `visual_nearby_and_cargo_localized`；目标雷达测距、地面或货物关联不可用时可使用视觉模型估距，来源为 `visual_distance_estimate`，返回 `visual_nearby_and_cargo_estimated`，不声称取得雷达位置。单独的视觉 `nearby` 不替代货物身份核对。无法取得任何位置时仍可在原 Graph 中换观察点，沿用原截止时间；身份不符、控制权改变或未停稳不重试。

配送选货由灯作为指挥官直接决定，不向狗征求选货意见。用户未指定货物时，灯依据新鲜观察优先选择离狗较近、容易接近、看起来方便推动且有一定体积的独立物品；地面色块、贴纸和站点标记留作目的地。观察只提供真实外形、相对远近与通路线索，不保证物品一定可推动，不规定固定距离、尺寸或物品种类；狗继续按货物特征核对身份，实际接触和推动仍由执行器及真实回执判定。

内部 `go2_push_cargo` 用于粗略定向推送。有目的地的 `go2_push_cargo` 通过 `operation=assess|approach|push` 分开观察、接近和推送，默认 `assess`。`assess` 取得同一货物与目的地的新鲜观察及粗略视图说明，返回 `assessed/final=false`，由原 Go2 Graph 判断当前是否可以直接推、是否需要接近或粗调。`approach` 只执行本次观察建议的接近距离并确认真实停稳，返回 `approached/final=false`，不扣半机身、货物半径或额外观察留距。必要的转向、平移由原 Go2 Graph 显式调用现有 `go2_move`；执行器不再自动计算共线站位、追加横移或转向，不要求机械角度共线，也不追逐地图格或 5 厘米站位。`push` 只执行明确的向前推送，不自动追加调整，不强制调整后或推送后重新观察。货物在画面下边缘、部分裁切或地面接触处不可见不作为推送门禁；已有原物体引用仍须保持。首次货物定位优先尝试雷达关联，失败才降级为视觉估距；同一订单固定首次选定的定位来源，视觉路径不再重试雷达，雷达路径丢失关联时报告受阻，不静默换源。接近与显式粗调沿用共享地图和既有运动检查；实际接触推送前读取机载避障原值，关闭并读回确认后，仅该向前推送步骤跳过云端障碍拦截。结束、失败或取消先停止再恢复原设置，旧连接清理不能操作替代连接。权限、目标代次、定位会话、动作账本和真实停稳判定继续沿用原执行链。直接对话与游戏在同一运行内绑定原货物与目的地；后续措辞变化或参数省略不更换订单，游戏沿用找货回执中的定位来源。视觉距离按相机相对机身的前置偏移转换到 odom，不混用距离起点。`directional_push_attempted=true`、`confirmation=directional_move_and_stop` 且 `stop.result=ok` 表示朝指定方向的推送尝试完成，不能证明货物实际位移或送达，`delivered=false`；未知运动或未确认停稳不能完成本单。只有本单首次观察已在目的地附近时，才可返回 `already_near_destination` 并明确本次未移动，不能用靠近后的投影变化跳过原推送。无目的地的基础推物测试保留原行为，仍核对动作后的新鲜货物观察。距离可为任意有限正数，不设固定步长。

视觉估算路线不要求特定货物高度、雷达地面测量或固定投影距离范围。视觉须辨认唯一货物及其图像框；有目的地时由 `assess` 核对目的地并提供粗略视图说明，原 Graph 选择必要动作或直接 `push`，不追加货物底部可见性要求。按请求或本次视觉建议距离执行，不截成固定长度。转向省略平移速度参数，复用普通相对转向的 z 轴默认值，不把前进用的 0.25 指令幅度套到转向。接近与换位仍检查完整障碍地图；实际接触推送按下述限定作用域关闭避障，控制权限、定位与真实停稳保持有效。有目的地的推送按方向尝试完成，无目的地的基础测试停稳后重新观察，均不能冒充实测货物位移。

配送请求仍携带已确认的 `destination`；游戏绑定的目的地不能通过省略参数降级为基础测试。目的地支持地面色块、小标记和物体标识，不要求最小图像面积、完整外边界、精确对位或货物完全覆盖。视觉输出同帧目标框、地面接触可见性、粗略距离和视图说明，供原 Go2 Graph 判断推送或粗调；观察时原本已在目的地附近的判定仍在像素坐标计算货物底部到区域可见框或物体底部的间隔，约一个货物可见宽度以内且粗略深度一致才视为附近。这是粗略视觉关系，不作为精确世界距离。原本已在附近且停稳得到确认时，返回 `delivered=true`、`confirmation=cargo_near_destination_and_stopped` 和 `destination_precision=approximate_visual_proximity`，明确本次未移动；方向性推送完成保持 `delivered=false`。游戏的灯色可作双方约定的站点指令，目标物体无需与灯同色，仍核对本单灯色与真实回执。

定向推送尝试完成与货物实际位移、送达分别报告，不把机器人运动改写为货物移动；货物原本已在目的地附近时，复核并确认停稳即可，不额外推送。接近、显式粗调和前进直接复用原有 Navigator、运动权限、动作账本、已完成的共享地图及停稳判定。运动循环不重新关联货物、不重建私有地图，不传递接触许可或原始货物点云。`assess` 的当前观察和步间货物引用供原 Graph 判断当前是否可推；货物感知读取共享地图，不单独建图。 首次雷达候选须与同帧视觉估距相容，冲突才选择视觉估计；来源选定后整单固定，视觉路径不再关联点簇，已选雷达路径丢失关联时报告受阻。粗略目标关系来自同一画面的可信观察，不混合不同来源估计生成必须到达的共线站位。接近与换位沿用完整共享地图避障。实际接触推送前读取机载避障原值，关闭并读回确认后，仅对这一向前推送步骤跳过云端地图障碍拦截；结束、失败或取消先停止，再恢复原设置。作用域由执行器绑定原目标、连接和定位会话，模型与浏览器不能声明关闭避障；不修改共享地图或重建私有地图。切换未确认不推送，恢复未知保留原运动结果，后续运动先补确认原设置。普通前进速度上限为 0.25 m/s，实际速度沿用共享加速度约束。

找物及导航作为复合任务前置步骤时遵守调用中的 `final=false`，默认单动作成功仍结束。推物的 `assess` 与 `approach` 均为前置步骤，成功由执行器返回 `final=false`；Go2 Graph 根据实际观察和回执决定继续推送或显式粗调，不另起决策循环。`push` 的方向尝试与真实货物位移、送达分别报告。直接对话与游戏在同一运行内绑定原货物与目的地；后续措辞变化或参数省略不更换订单，游戏沿用找货回执中的定位来源。视觉距离按相机相对机身的前置偏移转换到 odom，不混用距离起点。首次货物定位优先尝试雷达关联，失败才降级为视觉估距；同一订单固定首次选定的定位来源，视觉路径不再重试雷达，雷达路径丢失关联时报告受阻，不静默换源。雷达跟踪保留旧图像时间，不把旧目的地邻近判断当作送达证据。

推物不再根据货物框和机身尺寸构造观察停车距离、圆形绕行区或共线站位。观察给出的距离、方向和视图说明只供原 Go2 Graph 决定是否需要粗调，执行器不会将这些估计转换为必须追到的站位。接近和显式粗调仍使用共享地图；货物视觉推理结束后，在原定位会话与姿态稳定的条件下读取最新雷达快照参与首次关联，固定定位来源后不再换源。

找货与接近不设置固定步长、20 段或 20 米累计额度，Go2 对话不以固定模型轮次和动作次数终止；原任务期限、停止权限、定位和地图检查继续生效。视觉找物输出 `estimated_distance_m` 与 `advance_distance_m`，由现有 Navigator 执行建议目标，停止后再观察。目标雷达定位失败时，无论是否传入 `max_advance_m` 都可进入视觉找物；显式距离要求仅按剩余额度传递，不因降级扩大。避障地图或自身定位缺失仍不能移动。

推物候选在直接对话中必须同时核对可信入口保留的用户原话，不能只复述决策模型重写后的货物描述。视觉返回 `cargo_matches_user_request` 与画面依据；候选与原话的空间指代不一致或不确定时返回 `cargo_target_mismatch`，不执行移动。近处独立包装盒与远处堆叠纸箱须区分，口语中的“纸盒”不自动限定为棕色瓦楞纸箱。

目的地附近判定同时检查图像间隔和粗略深度：视觉输出 `destination_distance_m`，与货物估距使用同一尺度；深度缺失或差异超过约一个货物估计宽度时，不凭二维投影邻近宣布送达。此检查不限制本次移动距离。

观察时货物已经在目的地附近的成功回执标记 `progress=already_near_destination`、`motion_performed=false`、`cargo_motion_confirmed=false`、`movement=null`，观察保存在 `cargo_before`，不伪装成动作后的画面。Go2 直接回复沿用该工具事实，来源为 `tool_receipt`，不把目标原本满足条件改写成走过去或推过去；公开过程保留这些事实字段，聊天检查点保存实际对用户发出的说明。

## 控件与模式

`widgets[].states=[]` 表示所有状态；`placement` 为 `media` 或 `controls`，`order` 控制同区顺序，`visible=false` 隐藏。`requires_connection` 从 `connection_field` 读连接状态；`preview_only` 仅在预览选中当前态时显示。支持的类型只有：

| 类型 | 必填字段 | 派发 |
| --- | --- | --- |
| `led_color` / `color_swatches` | `action` | `/api/commands/{unit_id}`，可选 `swatches` |
| `connection` | `status_endpoint`、`connect_action`、`disconnect_action` | 状态读取同源端点，动作走命令 API |
| `joystick` | `action` | 命令 API 串行发送速度与停止 |
| `video` | 同源 `endpoint` | 优先读取同源 MJPEG 流，失败时回退到 `endpoint/snapshot?preview=true` 轻量快照；隐藏、断连或卸载时取消读取 |
| `map` | 同源 `endpoint` | 同源地图图像 |

摇杆可声明 `node_state`、`enter_action`、`exit_action`：选择对应节点时展开，或在已进入遥控时保持展开。节点和出入命令必须属于绑定区域的声明能力；进入命令被接受不会直接启用摇杆，仍等待实时 `enabled_when` 与动作门禁。双摇杆分别控制平移与转向，并合并为同一个速度向量；分别松手只清零对应分量，全部松手发送零速度，退出遥控发送停止命令。

Go2 每次连接及重连后的首次运动准备在身体就绪后取得 `ClassicWalk(true)`（Sport API 2049）的成功回执，再允许移动；摇杆和所有任务 Move 共用经典行走，正常速度刷新不重复切换步态。步态未确认时阻止移动，保留连接及停止能力。Go2 点击“移动”直接完成运动准备并显示摇杆，不显示单独的进入/退出操控按钮或摇杆上方的操作说明。服务端在已有姿态、租约与连接门禁内取得 `StopMove` 确认后才发布 `control_mode=remote`；准备过程不发送非零速度，也不进入控制机身姿态的 `BalanceStand`。手动摇杆以 Sport 请求包发送 `Move(1008)` 的 `x/y/z`，松杆及失联看门狗发送 `StopMove(1003)`；每个请求有独立 ID，不等待回包阻塞后续输入。点击站立退出操控；切换到其他身体动作前先停止速度控制。自主导航也使用同一 Sport Move 通道。

Go2 的姿态和动作在初始白板视口内全部可见，站立连接趴卧、坐下及下方动作。节点坐标及边缘留白均在画布范围内，默认无需平移寻找动作；默认显示状态转移连线。灯与 Go2 的实时状态通过白板节点标示，白板底部不再展示状态提示条。视频和地图从缩略图放大为页面内的有界浮窗，保持标题和对话入口可见，不调用全屏或遮罩整个页面。

区域可声明 `prepare_action:{via:"standing",action:"SPORT"}`。已确认坐姿或趴卧时，点击站立仅选择当前姿态对应的起身命令；点击以站立为起点的其他动作，通过 `SPORT` 的 `cmd` 与 `prepare_standing:true` 请求服务端准备。服务端 LangGraph 先执行起身，并等待同一连接、同一物理请求的站立完成回执，再发送目标动作。准备失败、身体反馈无效或急停均中止后续步骤。手动命令的 `dispatch_only` 保留手动请求准入，不取消页面对已知起始姿态的选择；关节反馈可用时仍等待实际动作变化及稳定目标姿态，超过短 HTTP 窗口通过已有任务查询取得完成结果。

站立在白板上始终只有一个节点。起始姿态尚未确认时，该节点等待设备反馈，不弹出“起立／坐姿起身”供用户猜选；收到真实坐姿或趴卧反馈后，再自动选择对应的起身命令。

未知 widget 会记录日志并跳过；已知 widget 缺必填字段或引用未知状态也跳过。控件可用 `state_field` 绑定指定区域字段，默认使用主区；`enabled_when` 为字段到 JSON 标量或标量数组的字典，逐项 AND 匹配，不支持表达式执行。`available_actions_field`、`blocked_actions_field`、`availability_key` 与区域的实时门禁语义相同。例如遥控摇杆声明 `enabled_when:{control_mode:"remote"}`，并绑定 `available_actions` 的 `Move` 键。

`modes[]` 给出 `id`、`label`、`options`、同源读取端点 `get` 和命令名 `set_action`。可选 `state_field` 绑定实时模式值，有该值时优先于初始化 GET 结果，避免其他入口改模式后本页仍高亮旧值。模式切换统一走 `/api/commands/{unit_id}`，服务端仍校验管理员权限和允许值。模式命令只声明 `set_action`，不再保留 `set` 回退字段。模式是配置，不代表设备当前活动或照明状态；灯的 `manual/reactive` 不改变其 `OFF/ON/BLINKING` 事实。

## JSON 直读入口

`/api/devices/{unit_id}/agent` 返回 Registry 收到的原始静态声明，按身份、通信、能力和界面分段，不附加运行状态。未发现原始卡时返回 404，不用离线占位设备拼装 Card。空行只分隔顶层字段组，JSON 保持可解析。

规则 API `/api/devices/{unit_id}/training` 按需从 `regions` 与 `skills` 生成能力目录；目录不回灌 Card，也不随 MQTT/SSE 的设备卡公告重复传输。稳定转换 ID 在唯一拓扑上声明，用户已保存的规则继续按这些 ID 引用。

聊天待确认事件卡片正文使用一句结构化说明，例如“看到主人时，切换到坐下。”或“开心时，闪烁 3 次。”，提供“先不添加”“确认并生效”，不重复堆叠事件参数详情。单步骤可展示“源状态 → 目标状态”；多步骤按动作顺序展示行为链，原始触发事件只出现一次，动作之间标明“完成后”，不得据此向设备状态机添加不存在的物理转换。同一步的多个 `transition_ids` 是备选源状态，不作为执行顺序重复展示。确认保存后先反馈已保存，仅当前确切版本获得执行器加载回执后展示“事件已生效”；生效卡沿用行为链与句式说明，右上方仅保留带 `aria-label="查看状态转移"` 的图标入口，定位连线并打开悬浮卡片，不进入聊天修改。动作显示名称由 Card 派生的 `catalog.presentation.actions` 提供，展示元数据不参与执行能力哈希。

Go2 视觉事件是整条已确认教导的启动事件：启动前检查本次新鲜观察，准入后在原运行内按顺序完成各步骤，人员或物体随后离开画面、原始观察过期均不撤销已经启动的行为。原观察保留真实时间及身份，不能投影为持续在场或新的身份确认；目标代次、明确停止或接管、连接 epoch、租约 generation、权限、规则版本、能力目录及实际姿态仍在执行边界复核。不得因观察消失重放已完成动作，超时或未知回执沿原任务查询。相同观察事件去重与运行互斥不构成冷却时间；用户未要求执行间隔时新教导的 `cooldown_s=null`，模型不得自行填写时间，不相关修改保留原配置，用户明确要求取消间隔时可清除。

教导过程沿统一 `agent_progress` 事实发布，保留确切规则 ID/版本、设备 epoch、run_id、step_id 和 step_index；同次运行保留各步骤结果，步骤成功不能代表整条行为完成。派发前拦截、取消及目标已满足而跳过都须有相应结果，跳过不能伪造成派发。整次结束的结果包含 `public_result.training_run_finished=true`、`step_count`（已完成步骤，含目标已满足而跳过）、`total_steps` 及真实 `result/error/step_index`，序号晚于该次步骤事实。界面分别显示配置保存/加载状态、步骤状态和整次完成进度；只完成第一步时显示部分完成，不从第一步回执补全后续动作。

执行器加载确认逐条校验设备归属、确切教导 ID、当前版本和保存的能力指纹；启用记录还必须匹配当前能力目录并通过定义校验。已删除、停用记录确认的是撤销，其保存的旧能力指纹无需匹配当前目录，不得因此阻断同批有效规则加载；确认撤销不会重新启用或执行该记录。

仅关联自定义事件的状态转移连线显示小圆点，点击后打开宽 280px、高度不超过 248px 的轻量悬浮卡片；窄屏或可用高度不足时继续收缩，不进入全屏或底部抽屉。标题和双向状态转移标签固定，内容在卡片内部滚动；方向按钮按文本宽度收缩，避免整块背景铺满卡片。双向连线始终显示顶部方向切换区，允许分别查看两个方向的真实预置事件；某一方向没有未删除的自定义事件时，不渲染该方向底部整个“自定义事件”区域（标题、分割线、空提示一起隐藏）。未启用事件仍属于可管理的自定义事件并保留该区域；删除最后一条自定义事件后立即隐藏该区域，但保留顶部方向切换。不设关闭叉，点击卡片外任意位置或按 Escape 关闭。双向连线按当前方向展示源状态和目标状态关联的全部事件，切换方向及保存时保持事件归属，不能把修改串到反方向。事件分为只读的“预置事件”和可编辑、删除的“自定义事件”；未启用事件保留并标明状态，已删除事件不展示。自定义事件使用与聊天卡一致的句式，参数直接嵌入当前卡片的文本输入框，情绪、枚举、数字参数仍依据原 schema 校验，不改为无约束字符串；非默认动作参数及多步骤内容不能因精简展示而隐藏或丢失。未修改禁用保存、保存中显示加载、成功反馈更新成功、失败保留输入并说明原因。状态转移使用 `trigger_condition` 声明完整一句话的预置事件说明；`event_label` 与独立的 `guard_label` 仅为旧卡保留说明回退。技能可声明 `parameter_labels:{参数键:展示名}`，由目录投影为 `catalog.presentation.parameters`，不改变参数校验或能力哈希。句式说明由结构化定义生成，不将模型的 `effect_text` 当作当前定义的说明。

管理员可通过 `PATCH /api/training/{teaching_id}/parameters` 在原卡片快速修改已有参数。请求包含 `expected_revision`、`capability_hash`，以及可选的 `event_params`、`event_target`、`steps:[{step_index,params}]`、已有的 `emotion` / `cooldown_s` 参数；已有执行间隔可显式传入 `cooldown_s:null` 取消，界面允许清空该输入。不得新增参数、由客户端指定事件 ID、修改动作、状态转移 ID、条件或步骤顺序，固定参数、只读参数及复杂值不开放快速编辑。服务端复制当前定义、复核参数类型/范围、冲突和版本，并沿用草案确认及执行器加载流程。此保存直接更新同一条自定义事件，不经过聊天确认，也不派发物理动作；内部 `source_kind=parameter_edit` 草案保留审计但不生成对话事件卡片。能力或版本变化时保留编辑内容并提示重新载入，不覆盖他人的新版本。

`event_target` 为无首尾空白、1–200 字符的自由文本事件参数，仅适用于原正向视觉事件（`recognized=true` 或 `detected=true`），不能与非空 `event_params` 同时提交。服务端将“主人”“陌生人”“人”“人脸”分别映射到对应的身份/在场事件，其他文本映射到 `vision.target_presence` 的 `target`，始终保留专用身份观察与普通物体观察的证据边界。转换前后的事件均须属于该设备声明的视觉事件族；目标事件仍须通过当前能力目录和首步骤 `training_events` 校验。不改动作、条件及步骤；仅保存文本不能证明主人在场。身份服务暂不可用不阻止保存未来事件，实际执行仍要求新鲜可信观察。未改变的保存不递增版本；改变参数后沿原 `teaching_id` 递增版本并等待新版本加载确认。

直接删除自定义事件使用 `DELETE /api/training/{teaching_id}`，请求体为 `expected_revision` 与当前目录 `capability_hash`，校验管理员 Cookie 会话、CSRF、版本及能力目录。服务端沿原保存/确认边界递增原事件版本并标记删除，保留历史；审计草案使用 `source_kind=parameter_edit`，不进入聊天，不由浏览器伪造自然语言原话。浏览器取得确切 ID、递增版本及 `desired_status=removed` 的有效回执后，立即移除对应事件和其活动高亮；其他事件保持，连线不再关联任何自定义事件时才移除圆点。后续目录/历史刷新不阻塞删除完成反馈，删除前发起的旧读取不能恢复已删除事件；请求失败或回执不完整时保留原事件。删除不派发物理动作。

模型的 `list_training` 从管理快照投影当前未删除记录，保留 `disabled` 状态、能力目录、当前定义及草案的确切 ID、版本、确认资格和失效原因；排除已删除记录、历史版本、原始 `source_text` 与审计连线注解。草案 `before` / `after` 及 `propose_training` 返回值同样不向模型传递历史或原始原话，草案以 `status` 区分 `pending`、`blocked`、`confirmed`、`cancelled`、`superseded`、`expired`。管理 API 与审计存储继续保留原记录。删除提交后该记录不再参与后续教导选择或步骤准入，不等待加载回执；历史留存不表示仍生效或待清理。查询本身不创建、保存或执行教导，查询或模型失败不得据此推测存在旧教导或待清理配置；已经准入或在途的物理动作仍按原任务记录与真实回执判断，配置删除不伪造动作停止结果。
